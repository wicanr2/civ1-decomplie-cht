# 編碼陷阱踩過: UTF-8 vs Big5

初版 text_out 走 Big5 walker, demo 標題 "文明帝國" 變 "æ...æ..."
(Latin1 mojibake)。

Root cause: C 編譯器把 source UTF-8 bytes 直接放進 string literal
(E6 96 87 = 文)。Big5 walker 把 E6 當 lead byte, 但 trail byte 0x96
不在 Big5 範圍 [0x40,0x7E] U [0xA1,0xFE] -> fallthrough 把 E6 當
單 byte 印成 U+00E6 (æ)。

Fix: 加 civ_utf8_walk, text_out 改走 UTF-8。Big5 walker 保留給未來
解 Track A patched binary 內 inline 字串用。

教訓 (應寫入 LESSONS_LEARNED 候選第 12 條):
  clean-room SDL2 重寫的 chokepoint 文字 walker 預設 UTF-8。原版
  dfCharSet 0x88 Big5 byte-pair walking 是 Win16 GDI 的事, 我們不
  該繼承。Big5 流程只在「直讀 Track A patched binary inline
  字串」這種特殊偵錯場合才用。
